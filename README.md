# 🎰 GGDROP CASINO — казино-бот для Wiftgram с мини-приложением

Полноценное казино внутри Wiftgram: бот на **Wiftgram Bot API** + мобильное
мини-приложение (WebApp) с восемью играми, балансом в **звёздах ⭐**, бонусами,
пополнением через хозяина и **панелью хозяина**.

- Бот: `@ggdrop_bot`
- Хозяин (владелец) казино: твой аккаунт (задаётся в `.env`, `OWNER_ID`)
- Кассир для пополнения: `@crypt` (меняется в панели хозяина)
- Всё локально: Node.js без единой внешней зависимости — `npm install` не нужен
- Данные в `data/db.json`, авторизация мини-приложения — подписанные токены
- Валюта виртуальная (`⭐`) — это игра, а не вывод реальных денег

---

## 1. Быстрый старт

1. Установи **Node.js LTS** (https://nodejs.org), версия 20+ (проверено на 26).
2. Двойной клик по **`start-all.cmd`** — поднимутся сервер и HTTPS-туннель.
   Либо отдельно: **`start.cmd`** (сервер) и **`tunnel.cmd`** (публичный адрес).
3. Открой в браузере `http://127.0.0.1:8080/app` — увидишь казино.
4. В чате с ботом отправь **`/start`** — бот выдаст приветственный бонус и кнопку казино.
5. Нажми «Открыть казино» — мини-приложение откроется внутри Wiftgram.

Проверка, что всё живо:

```
http://127.0.0.1:8080/api/health   →  {"ok":true,...}
```

## 2. Публичный HTTPS-адрес (обязательно для мини-приложения)

Клиент Wiftgram открывает WebApp только по `https://`. Три варианта:

### Вариант A — туннель Cloudflare (проще всего, 1 минута)

Запусти **`tunnel.cmd`** в отдельном окне. Скрипт:

- скачает `cloudflared.exe` в `tools\` (один раз, ~35 МБ);
- поднимет туннель на `http://localhost:8080`;
- получит адрес вида `https://random-words.trycloudflare.com`;
- запишет его в `data\tunnel-url.txt` — **сервер подхватит его сам** за 3 секунды
  и обновит кнопку «Открыть казино» у всех игроков, а хозяину придёт сообщение.

Окно туннеля нельзя закрывать, пока играете. Адрес «быстрого» туннеля меняется
при каждом перезапуске.

### Стабильный вход через GitHub Pages

Репозиторий содержит корневой `index.html` — легкую страницу-переход на текущий
бэкенд. Включи GitHub Pages для ветки `main` из корня репозитория и задай в `.env`:

```
GITHUB_PAGES_URL=https://<логин>.github.io/<репозиторий>/
```

После этого бот даёт стабильную ссылку на GitHub Pages, а страница сама
перенаправляет в `/app` на адрес из параметра `u`. При смене туннеля сервер
обновляет кнопку бота с новым адресом, а `backend-url.txt` служит запасным
адресом для старых ссылок и обновляется при публикации.

### Вариант B — свой домен + reverse proxy

Поставь на сервер nginx/Caddy с валидным сертификатом и проксируй на `127.0.0.1:8080`:

```nginx
server {
    listen 443 ssl http2;
    server_name casino.example.com;
    ssl_certificate     /etc/letsencrypt/live/casino.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/casino.example.com/privkey.pem;
    location / { proxy_pass http://127.0.0.1:8080; proxy_set_header Host $host; }
}
```

Затем пропиши адрес: **`tunnel.cmd -Url https://casino.example.com`**
или в мини-приложении: «Хост» → «Настройки» → «Публичный адрес приложения».

### Вариант C — самоподписанный сертификат (локальная сеть)

```
cert.cmd -Trust
```

Создаст сертификат для `localhost` и всех локальных IP, поднимет HTTPS на `8443`
и добавит сертификат в доверенные. Работает для браузера на этом же ПК и в
некоторых клиентах, которые используют системное хранилище сертификатов.
Если клиент Wiftgram всё равно отказывается открывать — используй вариант A или B.

## 3. Хозяин казино

Хозяин — это аккаунт с `id` из `OWNER_ID` в `.env`. Если `OWNER_ID=0`,
хозяином автоматически становится **первый**, кто напишет боту `/start`.
Текущего хозяина видно в логе при запуске и по команде `/whoami`.

### Что даёт статус хозяина

- 👑 вкладка **«Хост»** в мини-приложении;

- уведомления о крупных выигрышах игроков;
- управление балансами, лимитами, процентами казино, промокодами и рассылками.

## 5. Пополнение звёзд ⭐

Пополнение идёт **через хозяина казино**. В мини-приложении кнопка «＋» сверху
(или «Пополнить» на главной и в профиле) открывает шторку с суммой и заявкой.

1. Игрок выбирает сумму → «Создать заявку» → получает номер вида `#D1AB`.
2. Хозяину в бот сразу приходит сообщение с кнопками «✅ Зачислить» / «❌ Отклонить».
3. Игрок пишет кассиру **@crypt** и отправляет оффер/подарок со звёздами на эту сумму.
4. Хозяин подтверждает — звёзды падают на баланс, игроку приходит уведомление.

Заявки также видны в панели хозяина → вкладка **«Пополнения»** (там же история).
Ник кассира, минимальная и максимальная сумма задаются в «Настройки».

### Вывод звёзд и экономика

- Вкладка **«Вывод»** в мини-приложении: игрок указывает сумму и контакт, создаёт заявку.
- Сумма **сразу резервируется** — потратить её в играх нельзя; при отклонении возвращается автоматически.
- Хозяину в бот приходит сообщение с кнопками **«✅ Выплачено» / «❌ Отклонить»**.
  То же можно сделать командами `/withdrawals` и в панели → вкладка «Выводы».
- **Потолок баланса — 150 000 ⭐** (меняется в настройках). Всё сверху уходит
  в видимый «банк» игрока; хозяин может перевести оттуда обратно в панели.
- **Комиссия за хранение** (по умолчанию 0.5 % в сутки с суммы сверх 100 000 ⭐)
  начисляется раз в сутки. Она **не скрытая**: сумма и причина видны в профиле
  и в истории ставок, а параметры — в настройках хозяина.

### Лимиты

Автоматического ограничения кассы больше нет: блок «Защита кассы», банкролл,
дневные лимиты и лимит выплаты за раунд удалены из сервера, админки и интерфейса.
Старые настройки банкролла при запуске вычищаются из базы.

Остаются только:

- **потолок баланса** (по умолчанию 150 000 ⭐) — всё сверху уходит в видимый
  «банк» игрока и может быть выдано хозяином;
- **лимиты ставки** — общий (`maxBet`) и по играм (`limits`), плюс доступный баланс;
- **комиссия за хранение** — явно показывается в профиле и истории.

Выигрыши выплачиваются полностью, без урезания. Хозяин видит все начисления
в истории и заявках на вывод и контролирует обязательства вручную.

### Проверка аккаунта

Ссылка из кнопки бота привязана к Wiftgram-аккаунту через `user_id` в токене.
Если клиент передаёт подписанный `initData`, сервер дополнительно сверяет его
подпись и `query_id` — подменить ссылку другим аккаунтом нельзя.

**Важно:** текущие сборки Wiftgram не передают подписанный `initData` в WebApp.
Поэтому в `.env` включён совместимый режим `STRICT_ACCOUNT_CHECK=0`: вход по
токену работает у всех, а если WebApp отдаёт `initDataUnsafe.user.id`, сервер
всё равно сверяет его с токеном и блокирует чужую ссылку. Жёсткий режим `1`
можно включать только если клиент действительно шлёт подписанный `initData`.

**Честность.** Результаты считает только сервер, браузер их не присылает.
Краш использует provably fair: до раунда публикуется `SHA-256(seed)`,
после раунда — сам `seed`, точка взрыва = `HMAC-SHA256(seed, roundId)`.
RNG — `crypto.randomBytes`, не `Math.random`.

```

GET  /api/me               профиль + настройки
POST /api/daily            ежедневный бонус
POST /api/promo            {code}
POST /api/transfer         {toId, amount}
POST /api/withdraw         {amount, contact}
GET  /api/withdrawals
GET  /api/history          последние ставки
GET  /api/leaderboard      топ игроков

POST /api/roulette/bet     {bets:[{type,value,amount}]}
POST /api/dice/bet         {amount,target,over}
POST /api/coinflip/bet     {amount,side}
POST /api/blackjack/start  {amount}
POST /api/blackjack/action {id,action}
GET  /api/crash/state      состояние раунда
POST /api/crash/bet        {amount,autoCashout}
POST /api/crash/cashout    забрать по текущему множителю

GET  /api/admin/overview         только хозяин
GET  /api/admin/users?q=
POST /api/admin/user             {id,action,amount}

POST /api/admin/promo
POST /api/admin/broadcast        {text}
GET  /api/admin/withdrawals
POST /api/admin/withdraw        {id, approve, note}
```

Все запросы к `/api/*` (кроме `/api/session`) требуют `Authorization: Bearer …`.
Заголовок `X-Wiftgram-Init-Data` проверяется в жёстком режиме
`STRICT_ACCOUNT_CHECK=1`; в совместимом режиме он необязателен.

Ответы всегда `{ok:true,...}` либо `{ok:false,error,description}`.

## 9. Безопасность и анти-читинг

- Ставки и результаты считает сервер; клиент только рисует.
- Кэшаут в краше проверяется по серверному времени — «подкрутить» таймер нельзя.
- Токен мини-приложения подписан HMAC-SHA256 и живёт 12 часов.
- Если клиент шлёт `initData`, он проверяется по алгоритму Telegram (HMAC с токеном бота);
  Wiftgram сейчас его не шлёт, поэтому используется совместимый вход по токену.
- Проверяются лимиты, баланс, бан, техрежим; есть rate limit (40 запросов / 2 с).
- Файл базы пишется атомарно (tmp + rename), есть бэкап при повреждении.
- Секреты (`data/secret.key`, `.env`) не коммитятся — см. `.gitignore`.

## 11. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| Кнопка «Открыть казино» не открывает приложение | не задан публичный HTTPS: запусти `tunnel.cmd` или пропиши адрес в админке |
| `ACCESS_TOKEN_INVALID` в логе | токен отозван — перевыпусти `/token` у @BotFather и обнови `.env` |
| Бот молчит | `BOT_MODE=off` или сервер не запущен; смотри окно `start.cmd` |
| «Сессия истекла» | ссылка живёт 12 часов — открой казино из бота заново |
| Порт занят | поменяй `PORT` в `.env` (и передай порт в `tunnel.cmd 8090`) |
| Туннель не скачался | скачай `cloudflared-windows-amd64.exe` вручную в `tools\` или используй свой домен |
| Баланс «не тот» | хозяин мог изменить его в панели; все операции видны в истории игрока |

## 12. Важно

Валюта `WFT` — **виртуальная и внутриигровая**. Это развлекательный бот, а не
платёжный сервис: здесь нет ввода и вывода реальных денег. Не используй проект
для реальных азартных ставок — это незаконно в большинстве юрисдикций.
Играй ответственно.
